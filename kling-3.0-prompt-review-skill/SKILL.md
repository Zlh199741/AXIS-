## 审核标准

### 零、🔴🔴🔴 翻译审计检查（一票否决 — 必须在所有评分维度之前执行）

> **⛔ 一票否决规则**：翻译审计任一 🔴 项不通过 → **整体直接 FAIL**，无需进入后续五大维度评分。
> 翻译审计是质量的前置门槛，不是可选加分项。

对照 `translation-audit-rules.md` 中的14条翻译原则，逐条检查机读层：

| 检查项 | 要求 | 判定 |
|---|---|---|
| 术语零残留 | 机读层不得包含任何专业术语（mm数值、J-Cut、伦勃朗光、180度法则等） | 发现 → 🔴 FAIL |
| 铟面坐标零残留 | 使用标准位置词汇（画面左/右/近景/远景/深处）而非钟面方位 | 发现 → 🔴 FAIL |
| 原则覆盖度 | 每条提示词至少使用4条翻译原则 | <4 → 🟡 需补充 |
| 审计表 | 每条附带翻译审计表且内容准确 | 缺失/不准确 → 🔴 FAIL |

### 零-B、🔴 跨产物语义一致性自动化校验（2026-03-24 新增 — 根因修复）

- 🔴 运行：`python tools/validators/semantic-consistency-validator.py <集数>`
- 脚本自动比对：导演戏本 vs Kling 3.0提示词（动作/情绪/时长覆盖率）+ 角色提示词 vs Kling 3.0提示词（引用角色定义一致性）
- 🔴 脚本报告中有 critical 问题 → 该条直接 FAIL
- 🟡 脚本报告中有 warning → 人工复核
- 将脚本报告附入最终审核结论

### 零-C、🔴 原文溯源回查（2026-03-24 新增 — 根因修复）

- 如果 novel/ 目录存在原文小说文件：运行 `python tools/validators/novel-fidelity-checker.py <集数>`
- 🔴 角色行为与原文性格/能力矛盾 → 标记为必须修改

### 零-C2、🔴 跨平台画镜 Protocol 合规审核（2026-04-10 新增）

> 以下规则源自 seedance-storyboard-skill Protocol A/D/E，属跨平台通用铁律，Kling 3.0 同样适用。

| 检查项 | 要求 | 判定 |
|---|---|---|
| **Protocol A — 零代词** | 提示词完全无代词（他/她/它/男人/女人/主角/两人/他们），全部用 @角色名/@场景名/@物品名 | 发现代词 → 🔴 FAIL |
| **Protocol A — 道具引用** | 关键道具用 @物品名 引用且描述空间关系 | 道具未@或无空间关系 → 🟡 需补充 |
| **Protocol D — 视觉法医** | 提示词完全无抽象情绪/氛围词（悲伤/震撼/紧张/压抑/磅礴/凝重等），须替换为生理微反应或环境具象 | 发现抽象词 → 🔴 FAIL |
| **Protocol E — 防融图** | 多角色同框场景使用物理锚点描述（角色部位+接触物+画面方位），禁止笼统描述 | "两人对峙""众人围观" → 🔴 FAIL |
| **台词完整保留** | 导演讲戏本/剧本中的台词 100% 原文保留 | 缺字/改字/合并 → 🔴 FAIL |

- 🔴 标记项任一命中 → 该P块直接 FAIL
- 全部🟡累计 ≥ 3项 → 整体 FAIL

### 零-D、⚡ 动作戏打点架构专项检查（仅含"动作戏"场景类型标注的 P 块触发 — 2026-03-28 新增）

> **触发条件**：P块开头含 `场景类型：动作戏` 标注时，必须执行本节全部检查项，通过后才能进入后续五大维度评分。
> **⛔ 一票否决**：任一 🔴 项不通过 → 该 P 块直接 FAIL，整体审核结论为 FAIL。

**零-D-1 双轴声明检查**：

| 检查项 | 要求 | 判定 |
|---|---|---|
| 风格代号声明 | 人读层"双轴战斗声明"必须包含 SCI / WUX / MOD / FAN 之一 | 缺失 → 🔴 FAIL |
| 节奏模式声明 | 人读层"双轴战斗声明"必须包含 HEAVY / RUSH / CHASE 之一 | 缺失 → 🔴 FAIL |
| 场景类型行格式 | P块开头必须为 `场景类型：动作戏 \| 风格：[代号] × 节奏：[模式] \| 时长：Xs` | 格式不符 → 🟡 需补充 |

**零-D-2 打点时间轴蓝图检查**：

| 检查项 | 要求 | 判定 |
|---|---|---|
| 打点蓝图块存在 | 人读层必须包含"打点时间轴蓝图"块 | 缺失 → 🔴 FAIL |
| 打点时间戳标注 | 每个打点必须标注时间戳（格式：`@Xs` 或 `@X.Xs`） | 缺失 → 🔴 FAIL |
| 三层物理反馈完整 | 每个打点必须同时包含：①顿帧时长 ②震颤级别 ③风格对应粒子类型 | 缺少任一层 → 🟡 必须补充 |
| 打点总数与节奏模式匹配 | HEAVY: 4-5个/15s / RUSH: 10-15个/15s / CHASE: 2-3个/15s | 数量不符且无说明 → 🟡 需补充偏差理由 |
| RUSH专用打点簇 | 声明RUSH模式时，人读层应包含打点簇格式（N-1微顿轻击 + 1终结击） | 缺失 → 🟡 建议补充 |
| CHASE位移段标注 | 声明CHASE模式时，人读层必须有位移段描述（空间层转换/纵深推进/追逐距离变化） | 缺失 → 🟡 必须补充 |

**零-D-3 机读层打点翻译合规检查**：

| 检查项 | 要求 | 判定 |
|---|---|---|
| 顿帧参数零残留 | 机读层禁止出现 ms 数值（如"80ms""120ms"） | 发现 → 🔴 FAIL |
| 震颤级别零残留 | 机读层禁止出现"震颤X级"等技术级别描述 | 发现 → 🔴 FAIL |
| 速度坡道零残留 | 机读层禁止出现"0.3x""1.5x"等速度倍数数值 | 发现 → 🔴 FAIL |
| 风格代号零残留 | 机读层禁止出现 SCI / WUX / MOD / FAN 等缩写代号 | 发现 → 🟡 需替换为自然语言 |
| 机读层三层反馈存在 | 打点段必须包含：①"画面冻结约X秒" ②"高频震颤"等感知描述 ③风格对应粒子自然语言描述 | 缺少任一 → 🟡 必须补充 |
| 静默核弹绑定 | 打点前须有"全场声音骤然静默"或等效音效抽空描述 | 缺失 → 🟡 建议补充 |

**零-D-4 翻译速查表对照**（快速参考，与 translation-audit-rules.md 第二节联动）：

| 人读层参数 | 机读层合法表达 | 合规 |
|---|---|---|
| 顿帧80-150ms | 画面冻结约0.1秒 | ✅ |
| 顿帧20-50ms | 画面极短冻结一瞬 | ✅ |
| 震颤3-5级 | 强烈高频震颤 / 极强高频震颤 | ✅ |
| 速度坡道0.3x | 速度放慢至正常速度的三分之一 | ✅ |
| SCI粒子 | 蓝色电火花/金属碎屑/能量脉冲波纹/等离子弧光 | ✅ |
| WUX粒子 | 剑气弧光/内力气旋/落叶花瓣水滴崩碎/衣袂残片 | ✅ |
| MOD粒子 | 汗珠飞散/尘土/积水飞溅/衣物碎屑 | ✅ |
| FAN粒子 | 元素爆发（火/冰/雷/暗影）/符文崩解/灵魂残影 | ✅ |
| Bullet Time | 镜头360°环绕打击点，周围一切静止 | ✅ |

**评分细则**：
- 双轴声明（5分）：风格+节奏各2.5分，两者均需声明才得满分
- 打点蓝图精度（7分）：时间戳2分 + 顿帧2分 + 震颤1分 + 粒子2分；打点总数符合节奏模式规格可额外加1分（归入此项）
- 机读层翻译（5分）：发现任一🔴违规（ms/级别/倍率数字）→ 该项直接0分（已被零-D-3一票否决）；通过零-D-3后按自然度打分
- 运镜适配（3分）：对照 7.2 三节奏模式时间线框架核查

**可执行 Rubric（每子项 0/1/2 — 0=缺失/未达，1=部分达成，2=完整达成；消除主观打分）**：

> 用法：逐子项打 0/1/2 → 子项求和 → ×折算系数 = 该维度得分（四舍五入到整数）。任一标注「→ 触发零-D 一票否决」的子项得 0 时，该 P 块整体 FAIL（不再看总分）。
