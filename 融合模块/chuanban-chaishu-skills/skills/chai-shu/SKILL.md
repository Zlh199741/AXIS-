## 路由逻辑

### 选项 1（了解流程）

- 保持对话状态，回答用户对功能、依赖关系、工作流的提问
- 不触发任何工具调用，纯聊天模式

### 选项 2（拆新书）

1. 输出：「请提供书籍文件的绝对路径，或输入书名（支持模糊搜索）」
2. 若给路径 → 检查文件存在 → 直接进入 `chai-fen-sao-miao` 流程
3. 若给模糊书名 → Glob 搜索 `assets/novel-analysis/` 及桌面/Downloads 常见位置
   → 列出候选文件 → 用户确认 → 进入拆分扫描

### 选项 3（继续旧任务）

1. Glob 列出 `assets/novel-analysis/` 下所有一级子目录（书名列表）
2. 格式化展示，提示「请告诉我是哪本书，或直接输入项目路径」
3. 用户确认后：
   - 检查该目录下 `拆分/`、`概括/`、`人物和设定/`、`事件线/`、`ABC分析/` 是否存在
   - 若有 `_progress.json` 则读取进度
4. 综合判断各阶段完成度，以表格形式呈现：

   | 阶段 | 状态 | 说明 |
   |------|------|------|
   | 拆分 | ✅/❌ | 章节数 |
   | 概括 | ✅/🔄 X/Y组/❌ | 进度 |
   | 人物 | ✅/🔄/❌ | |
   | 事件 | ✅/🔄/❌ | |
   | ABC  | ✅/🔄 X/Y批/❌ | |

   **判断依据**：
   - 拆分：`{书名}/拆分/` 目录存在且有 .md 文件
   - 概括：`{书名}/概括/_progress.json` 的 completed_groups vs total_groups
   - 人物：`{书名}/人物和设定/_progress.json` 或角色地位.yaml 存在
   - 事件：`{书名}/事件线/_progress.json` 或事件线.yaml 存在
   - ABC：`{书名}/ABC分析/_progress.json` 的 batches_completed vs total_batches

5. 基于状态推荐「从哪里继续」，优先推荐未完成的最早阶段

## 欢迎引导

- 这是普通 `拆书` 用户的主入口，适合直接说"拆书 + 书名/路径 + 任务"
- 用户不需要自己记住子 skill 名称，主入口会按任务类型路由
- 为了避免误解，优先提供**绝对路径**，并明确写出**任务名称**
- 如果用户明确是弱模型、弱工具调用、长程指令遵循差的场景，应切到 `chai-shu-weak`

## 路径书写规则

1. 新书优先给"源文件绝对路径"
2. 已拆分或已开始的项目优先给"源项目目录绝对路径"
3. 不要只写模糊书名，除非你确认当前工作区里没有同名文件或同名目录
4. 如果你明确要测试弱模型链路，不要用原版入口，直接说 `弱模型特调版拆书`

## 工作目录

- 🔴 AXIS 规范工作目录（默认）：`{ROOT}/assets/novel-analysis/`（{ROOT} 为 AXIS 项目根，与 `融合模块/输出对接规范.md` 对齐）
- 已拆分项目目录格式：`assets/novel-analysis/{书名}/`
- 兼容旧路径：历史项目若位于 `Factory/拆书/{书名}/`，可继续读取；新项目一律落到 AXIS 规范路径，或在「全部完成后」同步至 `assets/novel-analysis/{书名}/`

## 执行前检查

- 功能 3-6 执行前必须检查前置依赖是否已完成
- 如未完成，直接提示用户先执行前置步骤，不要跳步

## 阶段衔接协议

当某个子阶段完成后，主入口必须执行以下行为：

### 概括完成后
1. 报告完成状态（共X组/Y章已完成）
2. 列出产出文件路径（概括目录、全书概括.md、名词表.md）
3. 呈现下一步选项：
   - 人物概括
   - 事件概括
   - ABC爽点分析
   - 全部按默认顺序执行（人物→事件→ABC）

### 任一分析项完成后
1. 报告完成状态 + 产出文件绝对路径列表
2. 呈现剩余可选项菜单（过滤已完成项）

### 全部完成后
1. 输出总结：列出所有阶段的产出文件绝对路径
2. 🔴 生成融合分析报告：在 `assets/novel-analysis/{书名}/融合分析报告.yaml` 写入汇总（字段以 `融合模块/输出对接规范.md`「融合分析报告模板」为准：基本信息 / 章节概览 / 人物分析 / 事件线 / 爽点分析 / AXIS接收）
3. 🔴 写入小说分析完成标记：在 `融合分析报告.yaml` 的 `AXIS接收` 段写入 `状态: 已就绪` + `接收时间`，作为「小说分析完成」标记，供 AXIS 判定是否可进入视频制作层
4. 🔴 指引进入 AXIS 视频制作层：提示用户输入 `~outline`（仅生成10集集纲）或 `~full`（完整流程），AXIS 将从 `assets/novel-analysis/{书名}/` 读取本次分析结果
5. 提示用户：可以用「小说问答」对分析结果做深入探讨

### 自动化拆书模式
- 顺序执行时，各阶段之间自动衔接，不暂停询问
- 但每个阶段完成后仍输出一行简报（如"✓ 分章节概括完成，12组36章"）
- 全部完成后执行「全部完成后」的行为

## 诊断指南

| 问题 | 检查 | 修复 |
|------|------|------|
| 用户不知道选哪个功能 | 展示功能菜单 | 推荐"自动化拆书"一键全流程 |
| 找不到已有项目 | Glob搜索assets/novel-analysis/ | 列出所有一级子目录供选择 |
| 某阶段状态判断错误 | 检查_progress.json和目录结构 | 按判断依据重新扫描 |
| 子阶段衔接中断 | 检查上一阶段是否完成 | 从最早未完成阶段重新开始 |
| 弱模型场景不稳定 | 检查模型能力 | 切到chai-shu-weak |
