# 事件线追踪（拟人确认模式）

先用现有资料直接梳理，产生疑问时再回到原文确认，最终综合归档。

---

## ⚠️ 关键约束（必读）

**梳理规则**：
- ✅ 只梳理核心主线 + 2-3个副主线，多了不归纳
- ✅ 感情线已在全书概括中总结，不作为事件线处理
- ✅ 最多10次回到原文阅读确认

---

## 编排模式

当由 `chai-shu` 主入口编排调用时（自动化拆书或用户选择了多项分析）：
- 跳过欢迎页输出
- 完成后返回状态摘要（完成数量、产出文件路径列表）
- 由主入口统一向用户呈现报告和后续选项

独立触发时（用户直接说"事件概括"等）：正常显示欢迎页。

---

## 前置依赖

必须先完成「分章节概括」，确保以下文件存在：
- `{书名}/概括/` 目录（章节概括文件）
- `{书名}/全书概括.md`
- `{书名}/人物和设定/名词表.md`

```
输出目录: {书名}/事件线/
```

---

## 执行阶段

```
阶段1：初次事件线梳理
    │
    ├─ 读取：全书概括 + 名词表 + 分章节概括
    ├─ 直接梳理核心主线 + 2-3个副主线
    └─ 输出：初次事件线追踪.md
    │
阶段2：审视与确认（拟人确认模式）
    │
    ├─ 主进程审视初次结果
    ├─ 如有疑问，回到原文阅读确认
    ├─ 撰写事件线笔记文档
    └─ 最多10次回到原文阅读
    │
阶段3：综合归档
    │
    ├─ 结合「初次事件线追踪」+「事件线笔记」
    └─ 输出：事件线.yaml + 时间轴.md
```

## AXIS 改编对接：事件 YAML 扩展字段（情绪类型 + 3-10-60 映射）

为打通下游「集纲生成 / 集数规划」，`事件线.yaml` 中每个事件条目在原有 `type` 基础上 **追加** 以下字段：

```yaml
storylines:
  main:
    events:
      - chapter_range: "31-33"
        title: "人性觉醒"
        type: climax                    # 原有：事件结构类型
        summary: "为保护沈怡月开启月之暗面"
        情绪类型: 升级                   # 新增 ENUM: 冲突|温情|悬疑|升级|反转|虐心
        改编映射:                        # 新增：3-10-60 映射，供集纲/集数规划直接对接
          建议集数: ep03                 # 建议改编为第几集
          建议时长: 90s                  # 该事件单元建议成片时长
          Hook: "暗面瞳孔骤变的特写"       # 前3秒钩子（对应 ABC 的 A）
          Climax: "一掌击溃围攻者"         # 1分钟爽点（对应 ABC 的 B）
          Cliffhanger: "黑屏前反派的冷笑"   # 卡点钩子（对应 ABC 的 C）
        abc关联: [ch031, ch032]          # 新增：本事件覆盖的 ABC 高密度/峰值章节
```

**字段规则**：
- `情绪类型`：标注事件的主导情绪，用于集纲的情绪周期（蓄能/加压/升级）排布
- `改编映射`：给出「建议改编集数 + 建议时长」，并按 3-10-60 拆出 Hook / Climax / Cliffhanger 三个落点
- `建议时长`累计可校验改编集数是否充裕（不足则拆事件，不删事件）

## 事件峰值 ↔ ABC 高密度章节关联

事件高潮必须与爽点峰值对齐，二者错位需复核：

- **峰值事件**（`type=climax` 或 `type=turning_point`）必须回填 `abc关联`，指向 `assets/novel-analysis/{书名}/ABC分析/abc-summary.yaml` 的 `top_chapters`（峰值章）或 `abc-heatmap.md` 中 `abc_density=高` 的章节
- 校验规则：峰值事件应落在 ABC 高密度区间内；若某高潮事件对应章节为 `abc_density=低`，标注「⚠️ 高潮—爽点错位」并回原文复核
- `dry_spells`（连续 3+ 章低密度）区间内的事件，集纲阶段应合并压缩，不单独成集
- 写入融合分析报告：本节关联结果汇入 `融合分析报告.yaml` 的 `事件线:` 节（结构见 `融合模块/输出对接规范.md`），峰值事件的 `abc关联` 供集纲选定高潮集

## 诊断指南

| 问题 | 检查 | 修复 |
|------|------|------|
| 前置文件缺失 | 检查概括/全书概括/名词表 | 先完成分章节概括 |
| 事件线太多 | 检查是否超过1主线+3副线 | 只保留核心主线+2-3个副主线 |
| 回原文次数超限 | 检查是否超过10次 | 基于现有资料归纳，不再回原文 |
| 事件因果链断裂 | 检查事件间是否有因果关系 | 补充缺失的因果连接 |
| 时间线混乱 | 检查事件时序是否正确 | 按章节顺序重新排列 |
| YAML格式错误 | 对照yaml-schema.md检查 | 按模板修正结构 |

## 术语表

| 术语 | 定义 |
|------|------|
| 拟人确认 | 先直接梳理→审视结果→有疑问回原文确认 |
| 核心主线 | 故事的主要情节线索 |
| 副主线 | 辅助主线的次要情节线，最多2-3条 |
| 事件线档案 | YAML格式的结构化事件数据 |
| 时间轴 | Mermaid格式的事件时序可视化 |
| 增量更新 | 仅处理新增章节，不重复已处理内容 |

## 质量标准

| 检查项 | 标准 |
|--------|------|
| 事件线数量 | 核心主线1条 + 副主线2-3条 |
| 因果逻辑 | 事件间有清晰的因果关系 |
| 时序正确 | 事件按时间顺序排列，无错乱 |
| YAML格式 | 事件线.yaml结构符合schema定义 |
| 原文确认 | 回原文次数≤10次 |
