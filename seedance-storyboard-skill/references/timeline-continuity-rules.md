## 七、时间轴规范（T0强制）

### 7.1 动作流程时间轴

```markdown
T+0.0s：[开场状态描述]
T+0.5s：[第一个动作/变化]
T+1.0s：[第二个动作/变化]
T+1.5s：[第三个动作/变化]
T+2.0s：[第四个动作/变化]
T+2.5s：[第五个动作/变化]
...
T+Xs：[结束状态描述]
```

要求：
- 精度：0.5秒
- 动作描述：具体物理动作，禁止心理描写
- 衔接锚点：T+Xs结束状态=下一镜T+0s开始状态

### 7.2 高燃节拍时间线（战斗场面 — 三节奏模式）

> 使用时先确认节奏模式（详见 3.2 双轴确认规则），再选对应时间线框架填写。

**HEAVY 重击型**（4-5个打点/15s，每击极重）：
```
0-2s   [建立]：对峙压迫氛围，沉稳运镜（Dolly Zoom / 缓绕）
2-4s   [蓄力]：发力预兆，速度坡道降至0.2x-0.3x
4-7s   [重击#1]：打点爆发 — 顿帧80-150ms + 震颤3-5级 + 大型粒子（扩散1-5m）
7-8s   [呼吸间隙]：0.3-0.5s停顿，受力方后效（踉跄/震荡/余烟）
8-11s  [重击#2]：打点爆发 — 参数同上，环境破坏加深
11-15s [余波定格]：轨道缓绕，展示破坏全景，镜头锁定
```

**RUSH 连击型**（10-15个打点/15s，密度如鼓点）：
```
0-2s   [快速切入]：手持跟拍骨架，快速建立对峙
2-5s   [连击簇#1]：3-4个微顿打点（20-50ms + 震颤1-2级）→ 终结击（标准顿帧+震颤3级）
5-6s   [换位]：位移过渡（0.1-0.2s间隙），甩镜跟随方向
6-10s  [连击簇#2]：3-4个微顿打点 → 终结击（加强），跳切机位
10-12s [换位]：短暂位移，抽帧处理（起势→命中瞬移感）
12-15s [大终结击]：密度最高连击 → 最强终结击定格
```

**CHASE 追逐闪避型**（2-3个打点/15s，命中是稀缺高潮）：
```
0-3s   [建立]：初始距离与空间层次，长镜头不间断跟拍
3-7s   [位移段#1]：全程高速（1.2-1.5x），环境粒子流，纵深轴推进
7-9s   [稀缺打点#1]：速度骤降至0.3x | 顿帧100-150ms | 震颤4-5级 | 可选Bullet Time
9-12s  [位移段#2]：再次高速，空间层转换，拉开/缩短距离
12-15s [稀缺打点#2 / 悬念定格]：第二次命中 或 以追逐状态卡点
```

### 7.3 自适应时间密度（Adaptive Time Density）

> 🔴 **2026-06-09 对齐说明**：**一个视频(一次生成)＝≤15s，内部可含多个镜头切换**（模型一次生成完成）。下表"时长"指**视频内单个镜头**的时长；一个 15s 视频可装 4–6 个这样的快切镜头。
> 短剧多为**快切**：对话/反打 1–4s/镜，多句/多机位可在**同一个视频内**连续切（模型完成），不必每镜一次生成。
> 只有**视频总长 >15s** 时才拆成下一个视频，视频之间用 @分镜图承接。权威以 `SKILL.md`「视频单元 + 镜头切换 + 接点分镜图」+ `stitching-and-shot-handoff.md` 为准。

固定4段时间轴不适合所有场景。根据内容复杂度选择时间轴粒度：

> 🔴 **台词镜时长按语速分档算**（慢戏 3–4 / 日常 4–5 / 快戏 5–6 字/秒），权威见 `SKILL.md`「时间段时长估算标准」；下表为**日常档**参考，慢戏更长、快戏更短，严禁一刀切。小动作叠说话不另计时。

| 场景类型 | 单镜时长(日常档) | 同镜头分段(非切镜) | 示例 |
|---------|------|---------|------|
| 快切对话/反打 | 2-3.5s | 1段 | 一句台词+微表情；多句可同一视频内切 |
| 单一情绪/空镜 | 2-6s | 1-2段 | 0-3s / 4-6s |
| 标准叙事单镜 | 3-6s | 2段 | 0-3s / 4-6s |
| 动作一镜到底 | 6-15s | 跟拍多beat(0硬切) | 高燃节拍（见7.2） |
| 情感特写 | 3-6s | 2-3段 | 含留白段·连续 |

**自适应规则**：
- 简单场景不要硬拆4段，2段即可，避免强行填充内容
- 动作密集场景可细分至7段，每段对应一个动作节拍
- 情感戏必须预留至少1个「留白段」（仅环境音+微表情，无台词无动作）
- 各段时长不必等分，按内容重要性分配（高潮段可占4-5秒，过渡段1-2秒）

#### 🔴 7.3.1 段内节拍密度校验铁律（Segment Beat Density Gate）

**底层原理**：director-skill 已定义"1 拍 ≈ 2.5 秒"。此规则将该约束从"整条P"下沉到"每个时间段"，防止内容堆积在短时间段内。

**节拍定义**（与 director-skill 一致）：
- 一个物理动作 = 1 拍（"跪下"1拍；"跪下→撑棺沿→抬头"3拍）
- 一次镜头运动 = 1 拍（推/拉/摇/环绕各算 1 拍）
- 一句短台词（≤10 字）= 1 拍；超过 10 字按 2 拍算
- 一次表情/微动作变化 = 1 拍（"眉心拧结"1拍；"眉心拧结→瞪眼→旱烟斗一顿"3拍）
- 同时发生的事合并为 1 拍（"猛然睁眼，额头渗汗"= 1 拍）

**强制校验公式**：
```
段内最大节拍数 = floor(该段时长秒数 ÷ 2.5)

示例：
  2秒段 → 最多 0 拍（2÷2.5=0.8 → 0拍，仅够留白/定格）
  3秒段 → 最多 1 拍
  5秒段 → 最多 2 拍
  8秒段 → 最多 3 拍
```

**对白专项约束**：
- 一句完整口型对白最低需要：`字数 × 0.4秒`，下限 2 秒
- 一句完整画外音/旁白最低需要：`字数 × 0.2秒`
- 示例："大伯，爷爷的嘴张着，是不是还有遗愿？"= 16字 → 至少 6.4秒
- 示例："莫乱讲！"= 4字 → 至少 2 秒
- 🔴 **两句对白不可塞入同一段**，除非该段时长 ≥ 两句对白最低所需秒数之和 + 1秒缓冲

**情绪转折约束**：
- 每次情绪转折（如"害怕→好奇"、"愤怒→压抑"）= 至少 2 秒过渡
- 情绪转折不可与对白同时压缩在同一段

**自检流程（每条P编写完成后必须执行）**：
```
对每个时间段：
  1. 数节拍数 B
  2. 算上限 Max = floor(段时长 ÷ 2.5)
  3. 如 B > Max → ❌ 超密，必须：
     a. 拉长该段时长（从相邻低密度段借时间）
     b. 或将该段拆成两段
     c. 或将部分内容移到相邻段
  4. 如该段含口型对白/画外音 → 额外检查最低所需秒数
  5. 如该段含情绪转折 → 额外检查 ≥2秒过渡
```

**反面案例（即本次 P01 的错误）**：
```
❌ 7-8秒（仅2秒）塞入：
   - 小阳跪地抬头（1拍）
   - 大伯贴柱握烟斗（1拍）
   - 小阳16字台词（2拍，需4.8秒）
   - 大伯4字台词（1拍，需2秒）
   - 眉心拧结+瞪眼+旱烟斗一顿（2拍）
   - 小阳缩脖低头+目光飘回（2拍）
   - 画面定格构图（1拍）
   总计：10拍，需要 ≥25秒，实际只给了2秒

✅ 正确做法：将7-8秒改为7-15秒（8秒），
   或拆成 7-10秒（对白段）+ 11-13秒（反应段）+ 14-15秒（定格）
```

#### 7.3.2 密度校验表（Segment Density Gate Table — 强制输出格式）

**底层原理**：密度校验必须以可见表格形式输出，与翻译审计表同级别强制。如果只在"脑内"执行而不输出表格，等于没有执行。

**每条P编写完成后，必须紧跟翻译审计表之后输出密度校验表**：

```markdown
#### ⏱ 密度校验（P01）

| 时间段 | 时长 | 动作节拍数 | 口型字数 | 画外音字数 | 最低所需秒数 | 判定 |
|--------|------|------------|---------|------------|------------|------|
| 0-3s   | 3s   | 1          | 0       | 0          | 2.5s       | ✅   |
| 4-8s   | 4s   | 1          | 0       | 0          | 2.5s       | ✅   |
| 9-15s  | 6s   | 2          | 16      | 0          | 11.4s      | ❌ 需拆分或延长 |

**总判定**：❌ FAIL（容量超载，必须拆 P 或延长）
```

**表格列定义**：
- **时间段**：机读层中的 `X-Ys` 段
- **时长**：该段持续秒数
- **动作节拍数**：数该段内的物理动作+运镜+表情变化（按7.3.1节拍定义）
- **口型字数**：该段需要嘴型同步的台词字数
- **画外音字数**：该段旁白、系统声、画外音字数
- **最低所需秒数**：`动作节拍数 × 2.5秒 + 口型字数 × 0.4秒 + 画外音字数 × 0.2秒`，口型段下限2秒
- **判定**：最低所需秒数 ≤ 该段时长 → ✅；否则 → ❌

**FAIL处理**：
- 任何一段 ❌ → 该条P不得继续，必须修复后重新输出密度校验表
- 修复方式：拉长段时长 / 拆段 / 移内容到相邻段（同7.3.1）

### 7.4 跨提示词衔接协议（Inter-Prompt Continuity Protocol）

各条提示词不是孤岛，必须系统性设计衔接关系：

**人读层增加「衔接声明」**：
```markdown
**与上一条衔接设计**：
- 画面衔接：上条P03结束画面为[江辰站在门口]，本条开场从[同一位置]开始
- 情绪衔接：上条情绪为[紧张]，本条开场延续紧张后逐渐转为[释然]
- 声音衔接：上条末尾的[脚步声]在本条开头0.5秒内继续存在（声音桥接）
- 光影衔接：上条冷白灯光 → 本条维持冷白，在第8秒转为暖光
```

**机读层衔接写法**：
```
❌ 无衔接：以@图片1中的江辰为主角...（每条提示词都像从零开始）

✅ 有衔接：承接上一段，江辰仍站在门口，冷白月光映在脸上。
           以@图片1中的江辰（黑发束冠）为主角，场景参考@图片3...
```

**衔接规则**：
- 相邻两条提示词的**结束画面**和**开场画面**必须可以无缝拼接
- 声音衔接：使用声音桥接（上条声音延续到本条开头0.5秒）实现平滑过渡
- 光影衔接：相邻场景的光影/色调变化必须有逻辑（不能上条暖光下条突然冷光无缘由）
- 情绪衔接：情绪变化必须渐变，禁止相邻提示词情绪突变（除非有叙事目的）
- 空间衔接：同一场景内的连续提示词，角色位置必须从上条结束时的位置继续

### 7.5 对白口型同步协议（Lip-Sync Protocol）

有台词场景需遵循口型同步最佳实践，确保嘴部动作与台词匹配：

**机读层写法**：
```
❌ 弱口型："角色说'我不会放弃'"
✅ 强口型："角色面朝镜头，嘴型随台词清晰张合，坚定地说：'我不会放弃。'"
```

**口型同步规则**：
- **面部可见**：台词出现时，角色面部必须朝向镜头或侧面可见嘴部，禁止背对镜头说话
- **嘴型描述**：关键台词前加"嘴型随台词清晰张合"提示模型生成口型动画
- **台词前后留白**：台词前留0.3秒（嘴部准备），台词后留0.3秒（嘴部闭合过渡）
- **情绪匹配**：台词的情绪标注必须与面部表情一致（不能表情平静但"愤怒地说"）
- **多人对话**：正在说话的角色嘴部清晰，非说话角色嘴部自然闭合或微表情反应

### 7.6 台词完整性审计铁律（Dialogue Completeness Audit — 强制）

**底层原理**：台词是剧本的骨架。来源剧本中的每一句台词都必须在机读层中完整出现，不得静默丢弃、张冠李戴、改写措辞。翻译审计检查的是"视听语言翻译覆盖率"，**不检查台词完整性**——因此需要独立的台词审计维度。

#### 7.6.1 台词审计规则

1. **100%原文保留**：来源剧本中的每一句台词必须原封不动出现在机读层中，禁止缩写/改写/合并/替换措辞
2. **说话人锁定**：台词的说话人必须与来源剧本/导演分析一致，禁止张冠李戴（如来源剧本写"父亲说"，机读层不得改为"大伯说"）
3. **零遗漏**：来源剧本覆盖行号范围内有N句台词，机读层必须有N句台词。缺任何一句 → FAIL
4. **创作添加标注**：如果机读层需要添加来源剧本中没有的台词（如群演反应），必须在人读层标注"[创作添加]"，且不得替代原有台词
5. **跨P重排审计**：如果提示词的P划分与来源剧本行号范围不完全对应，必须确保重排后所有台词仍然全部保留，无一遗漏

#### 7.6.2 台词审计表（强制输出格式）

**每条P编写完成后，必须在密度校验表之后输出台词审计表**（无台词的P标注"本条无台词 ✅"即可）：

```markdown
#### 🎭 台词审计（P01）

| # | 剧本行号 | 源剧本原文台词 | 说话人/来源 | 承载方式 | 机读层对应位置 | 逐字匹配 | 判定 |
|---|---|---|---|---|---|---|---|
| 1 | Lxx | "大伯，爷爷的嘴张着，是不是还有遗愿？" | 小阳 | 口型 | 9-15s段 @洛小阳 台词 | 100%一致 | ✅ |
| 2 | Lxx | "莫乱讲！" | 大伯 | 口型 | 9-15s段 @大伯 台词 | 100%一致 | ✅ |

**总判定**：✅ PASS（来源剧本2句 = 机读层2句，说话人一致，原文一致）
```

**审计流程**：
1. 从来源剧本当前行号范围中，提取所有带引号的台词及其说话人
2. 逐句在机读层中定位对应台词
3. 校验：原文是否100%一致、说话人是否一致
4. 如有创作添加的台词，单独列出并标注 `[创作添加]`

**FAIL条件**（任一触发即FAIL）：
- 来源剧本台词在机读层中找不到 → ❌ 遗漏
- 台词措辞被改写（哪怕一个字） → ❌ 篡改
- 说话人不一致 → ❌ 张冠李戴
- 创作添加台词未标注 → ❌ 未标注
